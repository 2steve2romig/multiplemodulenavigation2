## Change 9 — Cold Review Findings: Document-Level (`f41b0a0`)

### What and why
First cold review pass identified 7 findings across security and correctness. Addressed items:

**H-1 — Audit log mutability (blocker):** RLS alone does not protect against the service role key, which bypasses all RLS policies. Added a PostgreSQL trigger in `004_audit_hardening.sql` that fires `BEFORE UPDATE` and `BEFORE DELETE` for all roles (including service role) and raises an exception. This is the only mechanism that enforces 21 CFR Part 11 §11.10(b) immutability at the DB layer.

**H-2 — Expired site row blocks org access:** `unionEntitlements` was giving expired site rows priority over active org rows. An expired site entitlement is typically an accidental lapse (not a deliberate corporate suspension), so the fix lets expired and time-lapsed site rows fall through to the org row. Only `status='suspended'` site rows (deliberate action) continue to override org rows.

**M-1 — IP address from X-Forwarded-For:** Changed to take the **last** entry (not the first) from the proxy chain. Vercel appends the real client IP as the last entry; the first entry is client-controlled and can be spoofed. Added IPv4/IPv6 regex validation before storing.

**M-2 — RLS on org tables:** `organizations` and `org_entitlements` had no RLS. Migration 004 enables RLS on both with no policies (deny-all for client roles; service role unrestricted).

**L-1 — Resource index + filter:** Added `(resource_type, resource_id)` composite index on `audit_log` and exposed both as query params on `GET /api/audit-log`.

### Files changed
- `supabase/migrations/004_audit_hardening.sql` (new) — immutability trigger, RLS on org tables, resource index
- `api/_lib/audit.js` — IP extraction fix (last XFF entry + regex validation)
- `api/_lib/entitlements.js` — `unionEntitlements` fallthrough fix; `now` parameter added for testability
- `api/audit-log.js` — `resource_type` and `resource_id` filter params
- `docs/adr/ADR-008-21cfr-part11-audit-trail.md` — document transactional audit writes and actor_id tombstone as hard production blockers
- `test/unit/audit.test.js` — 2 new tests: proxy chain IP extraction, injection rejection
- `test/unit/entitlements.test.js` — 3 new tests: org-active+site-expired (org wins), time-lapsed site (org wins), suspended site (site still wins)

### Test coverage
81 tests total (41 unit, 40 integration) — all passing after this commit.

## Change 10 — Cold Review Findings: Code-Level (`57e7509`)

### What and why
Second cold review pass (code-level) confirmed 11 prior findings closed and identified 6 new findings. Addressed items:

**M-1 — Missing audit write on POST /api/organizations:** All other admin mutation routes (tenant create/update, entitlement create, org-entitlement create) had audit trail writes wired. `POST /api/organizations` was the only mutation without one. Added `organization.created` audit event.

**M-2 — CORS header fingerprinting:** `Access-Control-Allow-Methods` and `Access-Control-Allow-Headers` were emitted regardless of whether the origin was in the allowlist. Updated ADR-006 to match, with explicit warning that this env var must never be `true` in production or preview deployments.

**L-2 — Node.js version:** `engines.node` raised from `>=18.0.0` to `>=20.0.0` (Node 18 reached EOL April 2025).

**H-1 (fail-open audit writes) remains open** — documented in ADR-008 as hard production blocker. Audit writes must become transactional Supabase RPC calls before any regulated customer goes live.

## Change 1 — ADR-007: Org/Site Billing Hierarchy (`500dfc8`)

### What and why
SureTrend customers are food manufacturing orgs that may operate multiple production sites. Each site is a `tenant` in the platform. The previous model only supported per-site entitlements. This change introduces a two-level hierarchy: a corporate org can hold entitlements that all child sites inherit, while sites can also hold their own independent entitlements.

**Decision rule (site wins):** If both the org and the site have an entitlement for the same module, the site's row is authoritative. This allows a site to independently suspend a module the org has granted, without affecting other sites.

### Files changed

#### `supabase/migrations/002_org_hierarchy.sql` (new)
```sql
CREATE TABLE organizations (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  name       text NOT NULL,
  region     text NOT NULL DEFAULT 'us-east-1',
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE tenants ADD COLUMN org_id uuid REFERENCES organizations(id) ON DELETE SET NULL;

CREATE TABLE org_entitlements (
  id         uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  org_id     uuid NOT NULL REFERENCES organizations(id) ON DELETE CASCADE,
  module_id  text NOT NULL,
  status     text NOT NULL CHECK (status IN ('active', 'suspended', 'expired')),
  expires_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);

ALTER TABLE user_tenant_memberships
  DROP CONSTRAINT user_tenant_memberships_role_check,
  ADD CONSTRAINT user_tenant_memberships_role_check
    CHECK (role IN ('owner', 'globaladmin', 'admin', 'user'));
```
- RLS enabled on `org_entitlements` with tenant-scoped read policy.
- Role constraint updated to the confirmed 4-role model (owner / globaladmin / admin / user), replacing the prior `technician / supervisor` values.

#### `api/_lib/entitlements.js` — `unionEntitlements()` added
```javascript
function unionEntitlements(siteRows, orgRows) {
  const map = new Map();
  for (const row of orgRows) map.set(row.module_id, row);
  for (const row of siteRows) map.set(row.module_id, row); // site wins
  return Array.from(map.values());
}
```
Pure function. Site rows are written second so they overwrite org rows on the same `module_id`. Tested in 6 unit tests covering: org-only, site-only, distinct union, site-wins conflict, empty inputs, deduplication.

#### `api/modules.js` — rewritten to implement org/site union
Logic:
1. Resolve `org_id` for the requesting tenant (nullable — sites without an org skip step 2).
2. Fetch site entitlements and org entitlements in parallel.
3. Call `unionEntitlements(siteRows, orgRows)`.
4. Filter to active/non-expired.
5. Join against module manifests.
6. Annotate each manifest with `_source: 'org' | 'site'`.

`_source` is `'org'` only when the module came exclusively from the org level (no active site-level entitlement exists for that module). If both levels have the module, `_source` is `'site'`.

#### `api/organizations.js` (new) — `POST /api/organizations`
Admin-only route (requires `X-Admin-Secret`). Creates an organization row. Validates with `OrgCreateSchema` (name, region). Returns `201 { organization }`.

#### `api/org-entitlements.js` (new) — `POST /api/org-entitlements`
Admin-only route. Grants a module to an org. Validates with `OrgEntitlementCreateSchema` (org_id UUID, module_id, status enum, optional expires_at ISO datetime). Returns `201 { org_entitlement }`.

#### `api/tenants/[id].js` — added `PATCH` method
Admin-only `PATCH /api/tenants/:id` assigns `org_id` to a site. Validates tenant ID as UUID (400 on invalid). Validates body with `TenantPatchSchema` (org_id UUID). Returns `200 { tenant }`.  
`GET /api/tenants/:id` was also updated to include `org_id` in the returned tenant fields.

#### `api/_lib/validate.js` — three new schemas added
- `OrgCreateSchema`: `{ name: string(1-255), region: enum(['us-east-1']) }`
- `OrgEntitlementCreateSchema`: `{ org_id: uuid, module_id: string(1-64), status: enum, expires_at?: datetime | null }`
- `TenantPatchSchema`: `{ org_id: uuid }`

## Change 3 — Bug Fix: IQAppView crash on API-sourced modules (`100db6a`)

### Problem
`IQAppView.jsx` destructured `p.stats.open` unconditionally. API-sourced module manifests (returned by `/api/modules`) do not carry a `stats` field — only the legacy in-memory `window.IQ_CATALOG` entries have it. Clicking any org-inherited module (e.g. Supplier IQ, which has no in-memory entry) caused an uncaught `TypeError: Cannot read properties of undefined (reading 'open')`.

### Fix
```javascript
// Before
const s = p.stats;

// After
const s = p.stats || { open: '—', openDelta: 0, completed: '—', onTime: '—', passRate: '—' };
```
Fallback uses em-dash display values so the UI renders gracefully with no data rather than crashing.

## Change 7 — ADR-008 Phase 1: 21 CFR Part 11 Audit Trail (`e14ee75`)

### Why this matters
FDA 21 CFR Part 11 §11.10 is a hard blocker before any regulated customer goes live. It requires an immutable audit trail with ALCOA+ properties (Attributable, Legible, Contemporaneous, Original, Accurate — plus Complete, Consistent, Enduring, Available). This change implements the platform-layer infrastructure (Phase 1 of 3).

### `supabase/migrations/003_audit_log.sql` (new)

```sql
CREATE TABLE audit_log (
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  actor_id      text,
  actor_type    text        NOT NULL CHECK (actor_type IN ('user', 'system', 'admin')),
  occurred_at   timestamptz NOT NULL DEFAULT now(),
  event_type    text        NOT NULL,
  tenant_id     uuid        REFERENCES tenants(id)      ON DELETE SET NULL,
  org_id        uuid        REFERENCES organizations(id) ON DELETE SET NULL,
  resource_type text        NOT NULL,
  resource_id   text        NOT NULL,
  before_state  jsonb,
  after_state   jsonb,
  ip_address    text,
  user_agent    text,
  request_id    text
);

CREATE TABLE electronic_signatures (
  id            uuid        PRIMARY KEY DEFAULT gen_random_uuid(),
  audit_log_id  uuid        NOT NULL REFERENCES audit_log(id),
  signer_id     text        NOT NULL,
  signer_name   text        NOT NULL,
  meaning       text        NOT NULL,
  signed_at     timestamptz NOT NULL DEFAULT now(),
  record_hash   text        NOT NULL
);
```

**Immutability enforcement:**
- RLS is enabled on both tables.
- **No UPDATE or DELETE RLS policies are defined** for any role (authenticated or anon). Only the service role (used server-side) can INSERT via the Supabase service role key, which bypasses RLS.
- `occurred_at` defaults to `now()` server-side — client-supplied timestamps are never trusted.

**Indexes:**
- `(tenant_id, occurred_at DESC)` — primary audit query pattern
- `(org_id, occurred_at DESC)` — org-level queries
- `(event_type, occurred_at DESC)` — filtering by event type

### `api/_lib/audit.js` (new)

```javascript
async function writeAuditLog(event) {
  const { error } = await supabase.from('audit_log').insert({ ...event });
  if (error) {
    console.error('[audit] WRITE FAILED', { event_type, resource_type, resource_id, error });
    // Intentionally does not throw — fail-open per ADR-008
  }
}
```

**Fail-open design (intentional per ADR-008):** A failed audit write logs `console.error` but never throws. The primary business operation is not rolled back due to an audit failure. The ADR documents this explicitly: "fail-open for the business operation, fail-loud for observability."

`requestContext(req)` extracts `ip_address` (from `X-Forwarded-For`), `user_agent`, and `request_id` (from `X-Request-ID`) from the Express request object.

### Audit writes wired into mutation routes

All four mutation routes that operate on regulated data now call `writeAuditLog()` after a successful database write:

| Route | Event type | `actor_type` |
|---|---|---|
| `POST /api/tenants` | `tenant.created` | `admin` |
| `PATCH /api/tenants/:id` | `tenant.updated` | `admin` |
| `POST /api/entitlements` | `entitlement.created` | `admin` |
| `POST /api/org-entitlements` | `org_entitlement.created` | `admin` |

Each audit record includes: `tenant_id` or `org_id` (scope), `resource_type`, `resource_id`, `after_state` (full row JSON), plus request context (IP, user agent, request ID).

### `api/audit-log.js` (new) — `GET /api/audit-log`

Admin-only read route (requires `X-Admin-Secret`). Returns paginated, time-ordered audit records.

**Query parameters** (all optional):
- `tenant_id` — filter to a specific site (UUID, validated)
- `org_id` — filter to a specific org (UUID, validated)
- `event_type` — filter to a specific event type string
- `from` / `to` — ISO datetime bounds on `occurred_at`
- `page` — 1-based (default: 1)
- `limit` — records per page, max 200 (default: 50)

**Response:** `{ audit_log: [...], total: number, page: number, limit: number }`

## Architecture context for reviewer

### What is NOT changed (still deferred)

- **Authentication** — all routes use a shared `ADMIN_SECRET` header for admin mutations. Public reads accept `X-Tenant-ID` header without verification. ADR-004 documents this as intentional for the prototype phase.
- **ADR-008 Phase 2** — electronic signatures (`electronic_signatures` table is created but nothing writes to it). Required per-IQ-module, not at the platform layer.
- **ADR-008 Phase 3** — system validation protocol (IQ/OQ/PQ per FDA guidance). Required before any regulated customer goes live.
- **`minRequiredRole` enforcement** — module manifests carry this field but it is not enforced server-side (display only). Will be enforced when auth is wired.

### Security constraints that must remain in force

1. `SUPABASE_SERVICE_ROLE_KEY` is server-only — never exposed to the React client bundle or any environment variable prefixed `NEXT_PUBLIC_` / `VITE_`.
2. `ADMIN_SECRET` is server-only — never client-visible.
3. `ALLOWED_ORIGINS` — no route uses `Access-Control-Allow-Origin: *` on any endpoint that carries tenant data.
4. `X-Tenant-ID` dev header is only accepted when `ALLOW_DEV_TENANT_HEADER === 'true'` (Vercel env var).
5. `.env.test` (contains `ADMIN_SECRET` and `SUPABASE_ANON_KEY`) is gitignored and must not be committed.

### Known limitations (by design for prototype)

- No real user identity — `actor_id` in audit records is always `'system'` or `'admin'` (a static string). When auth is wired, this will be replaced with the authenticated user's JWT subject.
- No rollback on audit failure — fail-open is intentional; the primary operation succeeds even if the audit write fails.
- No row-level before/after capture for GET requests — only mutation routes write audit records.

## Review focus areas (suggested)

1. **Immutability guarantee** — Is the RLS approach (no UPDATE/DELETE policies, service role bypasses) sufficient for 21 CFR Part 11 §11.10(b), or does the reviewer see a way the service role key could be used to mutate audit records?
2. **`unionEntitlements` correctness** — Is the site-wins-on-conflict logic correct? Edge cases: same module_id in both, org row suspended but site row active, site row expired but org row active.
3. **`_source` annotation accuracy** — The annotation is computed server-side by comparing `siteActiveIds` (active site entitlements) vs `orgActiveIds` (active org entitlements). Is the logic correct for the case where both levels have an entitlement?
4. **Fail-open audit writes** — Is it acceptable under 21 CFR Part 11 for the primary operation to succeed when the audit write fails? ADR-008 argues yes (with alerting), but the reviewer may have a different read of the regulation.
5. **Admin secret as auth** — Is the shared `ADMIN_SECRET` approach acceptable for a prototype? What is the migration path to per-user auth for admin routes?
6. **Schema review** — Any missing constraints, indexes, or RLS policies on `audit_log`, `org_entitlements`, or `organizations`?
